# 第五堂：Hardening（錯誤處理、Rate-limiting、資安、Scalability）

[← 回課程總覽](../README.md)

## 課程目標

學會用「奧客壓力測試」的思維檢視系統的脆弱點，並補強上線前必要的防護。

## 開通帳號

無新帳號需求（沿用前面已開通的服務做強化與測試）。

## 需要的背景知識

- **Rate limiting 概念**：請求頻率限制、為什麼要防護
- **常見資安概念**：最小權限原則、資料遮罩／加密
- **Scalability 基本概念**：併發、負載

## 課堂內容

- 複習作業：WhatsApp／電話串接結果（討論自行串接時遇到的坑）、奧客情境腳本與脆弱環節清單
- 錯誤處理：API 逾時／失敗、LLM 回覆格式錯誤、Context 檢索不到資料時的 fallback 設計
- Rate-limiting：避免單一使用者或惡意腳本灌爆 Agent 與後端 API
- 資安：處理客戶個資（門號、帳務）時的權限控管與資料遮罩
- Scalability：從一個測試案例到 Blazz 全公司規模，架構上要注意什麼
- 導入真實奧客情境進行極限對話測試，驗證上述強化措施

### 90 分鐘 Rundown

| 時間 | 內容 |
| --- | --- |
| 0:00–0:10 | 複習作業：WhatsApp／電話串接結果、奧客情境與脆弱環節清單 |
| 0:10–0:30 | 錯誤處理與 fallback 設計 |
| 0:30–0:45 | Rate-limiting 設計 |
| 0:45–1:00 | 資安：權限控管與資料遮罩 |
| 1:00–1:15 | Scalability 討論、導入奧客情境極限測試 |
| 1:15–1:30 | 成果展示、總結 |

## 課程 Deliverables

通過奧客情境壓力測試、具備錯誤處理／rate-limiting／資安／scalability 強化的完整系統；期末成果展示。

## 課後練習

無（最後一堂，課堂內完成成果展示、總結、後續發展建議）。
